## 什么是 Fabric IQ？

**Microsoft Fabric** 是一个统一的分析平台，把数据工程、数据科学、实时分析和商业智能放在一起。**IQ** 是 Fabric 的一项能力，让用户用**自然语言**提问，直接从结构化数据里拿到答案，不必写 SQL。

关键在于**本体**：它形式化地描述实体类型、属性以及关系。IQ 读取本体，理解数据的形状，再把用自然语言提出的问题翻译成正确的查询。

## IQ 如何使用本体

用户问*「上个月各区域的总销售额是多少？」*时，IQ 需要知道：

1. **实体类型**——`Order`、`Store`、`Region`
2. **属性**——`Order.totalAmount`、`Order.date`、`Store.region`
3. **关系**——`Order` → `placedAt` → `Store`，`Store` → `locatedIn` → `Region`
4. **标识属性**——哪些字段能唯一标识每个实体（例如 `Order.orderId`）

这四样东西都由本体提供。没有本体，IQ 分不清「门店」和「商品」，也不知道该怎样把两者连起来。

## 实体类型

实体类型是业务对象的类别。在 Fabric IQ 里，每个实体类型：

- 有一个**名称**和可选的**描述**
- 包含一个或多个**属性**（带类型的列）
- 必须至少有一个**标识属性**，用来唯一标识实例

可以把它想成一张表的定义：`Customer(customerId, name, email, tier)`。

## 属性与类型

每个属性都有数据类型：

| 类型 | 说明 | 示例 |
|------|-------------|---------|
| `string` | 文本 | 客户名称、商品 SKU |
| `integer` | 整数 | 数量、年份 |
| `decimal` | 小数 | 价格、评分 |
| `date` | 日历日期 | 下单日期、出生日期 |
| `datetime` | 带时间的日期 | 创建时间戳 |
| `boolean` | 真 / 假 | 是否有效、是否会员 |

**标识属性**（带钥匙图标）格外关键：它告诉 IQ 该怎样正确地对实体计数、分组和连接。

## 关系与基数

关系把实体类型连起来。每个关系都要说明：

- **源实体类型和目标实体类型**
- **名称**（一个动词：「places」「contains」「worksAt」）
- **基数**——两端各能连多少个实例

| 基数 | 含义 | 示例 |
|------------|---------|---------|
| 一对一 | 每个 A 恰好对应一个 B | `Employee` → `Badge` |
| 一对多 | 每个 A 对应多个 B | `Customer` → `Order` |
| 多对一 | 多个 A 对应一个 B | `Order` → `Store` |
| 多对多 | 多个 A 对应多个 B | `Student` → `Course` |

IQ 靠基数生成正确的聚合。`Customer` 与 `Order` 之间是一对多关系，所以「每个客户有多少订单」这种问法成立，而「每个订单有多少客户」通常只会得到 1。

## 为 IQ 设计本体

为 Fabric IQ 构建本体时，可以照着下面几条来：

1. **给实体起清楚的名字**——用用户嘴里的业务词（「Customer」，而不是「tbl_cust」）
2. **写描述**——IQ 会借助描述区分相似概念
3. **标出标识属性**——每个实体都必须至少有一个标识属性
4. **设置基数**——帮 IQ 生成正确的 GROUP BY 和 JOIN 逻辑
5. **保持聚焦**——只建用户会查询的概念，不必把每张内部表都搬进来

## 要点回顾

- Fabric IQ 借助本体把自然语言问题翻译成 SQL
- 实体类型、属性、关系、基数，这四样缺一不可
- 每个实体都需要标识属性，计数和连接才准确
- 名字起得好、描述写得清，IQ 回答问题的准确率更高
- 用 [本体设计器](#/designer) 可视化地创建适合 IQ 的本体

```quiz
Q: 在 Fabric IQ 中，为什么每个实体类型都必须有标识属性？
- 让本体看起来更专业
- 告诉 IQ 如何正确地计数、分组和连接实体 [correct]
- 用作实体的显示名称
- 设定默认排序顺序
> 标识属性唯一区分同一实体类型下的各个实例。没有它，IQ 翻译出的 SQL 无法正确执行 COUNT、GROUP BY 或 JOIN。
```

```quiz
Q: 关系的基数告诉 Fabric IQ 什么？
- 画关系时该用什么颜色
- 关系两端各能连接多少个实例 [correct]
- 关系是可选的还是必填的
- 实体显示的先后顺序
> 基数（一对一、一对多、多对一、多对多）告诉 IQ 如何生成正确的聚合和连接，比如它需要知道一个客户可以有多个订单。
```
