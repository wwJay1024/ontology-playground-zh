## 记录临床发现

一次就诊会产生临床发现——患者得了什么病？**诊断**实体用标准化编码记录这些发现。

加入诊断之后，就可以回答：

- “哪些患者被诊断出糖尿病？”
- “上个季度哪位服务提供方发现的重症最多？”
- “各科室最常见的诊断是什么？”

## 诊断实体

| 属性 | 类型 | 是否标识属性 |
|---|---|---|
| `diagnosisId` | string | ✓ |
| `icdCode` | string | |
| `description` | string | |
| `severity` | string | |
| `diagnosedDate` | date | |

`icdCode` 属性存放标准化的 ICD（国际疾病分类）编码——一套全球通用的编码体系。有了它，本体就能与保险、计费和科研系统互通。

## 新增关系

- **diagnosed_with**——`Patient` → `Diagnosis`（一对多）
  一名患者在其病史中可以有多个诊断。

- **diagnoses**——`Provider` → `Diagnosis`（一对多）
  服务提供方根据临床评估记录诊断。

> **双重归属：** 诊断既连接患者（谁得了这个病），也连接服务提供方（谁发现了这个病）。这双重连接让两种视角都成立：以患者为中心看“我的全部病情”，以服务提供方为中心看“我诊断过的全部病例”。

## 小结

- **标准化编码**（ICD）让本体能与外部系统互通
- **双向连接的实体**（患者 → 诊断 ← 服务提供方）同时承载两种视角
- **严重程度属性**支撑风险分层与临床优先级排序
- 图谱现在既能做排班查询（经预约），也能做临床查询（经诊断）
