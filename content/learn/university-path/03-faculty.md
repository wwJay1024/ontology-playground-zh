## 加入教职员工

谁在教这些课？**教授** 实体补上了"教"这个维度——把教职员工连到课程，进而连到学生。

有了 教授，就可以问：

- "哪位教授教的 400 级课程最多？"
- "Smith 教授所授课程的平均 GPA 是多少？"
- "哪些终身教授在教入门课？"

## 教授 实体

| 属性 | 类型 | 是否标识属性 |
|---|---|---|
| `professorId` | string | ✓ |
| `name` | string | |
| `rank` | string | |
| `tenured` | boolean | |
| `officeHours` | string | |

`rank` 属性（Assistant、Associate、Full）体现学术层级。`tenured` 是布尔值，支持围绕职业稳定性和学校投入的查询。

## 新增关系

- **teaches** — `教授` → `课程`（一对多）
  一位教授每学期教一门或多门课。

- **advises** — `教授` → `学生`（一对多）
  教授指导自己学位项目里的学生。

> **传递查询：** 有了 教授 → 课程 ← 选课 ← 学生 这条链路，就可以提出跨越授课关系的问题："哪些学生在上终身教授的课？"这需要依次走过 教授 → 课程 → 选课 → 学生。

## 我们学到了什么

- **布尔属性**（tenured）形成是/否分类，便于筛选
- **传递查询**沿着多条关系走到远端实体
- **学术职称**遵循既定层级（Assistant → Associate → Full）
- 图谱现在既能回答以学生为中心的问题，也能回答以教师为中心的问题

```quiz
Q: 在高校本体里，传递查询是什么样子？
- 查询单个实体的属性
- 沿 教授 → 课程 → 选课 → 学生 这样的多条关系，把远端实体连起来 [correct]
- 按 ID 查一位教授
- 统计系统里的课程数量
> 传递查询是基于图的本体最有力的地方之一。沿着 教授 → 课程 → 选课 → 学生 走一遍，就能回答"哪些学生在终身教授的班上？"——把没有直接关系、但通过中间节点相连的实体连起来。
```
