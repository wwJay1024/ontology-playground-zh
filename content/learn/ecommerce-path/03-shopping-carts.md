## 购买之前

并不是每次浏览都会变成购买。**购物车** 记录的是买家结账前正在考虑的东西。它是一个会话实体，临时且可变。

加入购物车之后，就能回答：
- 「本周有多少购物车被放弃？」
- 「平均购物车金额与平均订单金额相比如何？」
- 「哪些商品最常被加入购物车却始终没有下单？」

## Shopping-Cart 实体

| 属性 | 类型 | 是否标识属性？ |
|---|---|---|
| `cartId` | 字符串 | ✓ |
| `createdAt` | 日期时间 | |
| `itemCount` | 整数 | |
| `subtotal` | 小数（USD） | |

`itemCount` 与 `subtotal` 是反范式的汇总属性。它们本可以从购物车内容算出来，直接存下来是为了查询更快。

## 新关系

- **has_cart**——`买家` → `Shopping-Cart`（一对一）
  每个买家恰好有一个活跃购物车，每个购物车也恰好属于一个买家。

- **contains**——`Shopping-Cart` → `商品`（多对多）
  一个购物车可以放多个商品，一个商品也可以出现在很多购物车里。

> **一对一模式：**`has_cart` 之所以是一对一，是因为每个买家只有一个活跃的购物会话。这与订单（一对多）不同：订单会随时间累积，而购物车在任何时刻只有一个。

## 小结

- **会话实体**用于表达临时或进行中的状态（购物车、草稿、会话）
- **一对一关系**规定了严格的配对（一个买家 ↔ 一个购物车）
- **反范式属性**（itemCount、subtotal）用存储空间换查询速度
- 购物车分析能带来**转化漏斗**方面的洞察（购物车到订单的比率）

```quiz
Q: 为什么 买家 与 Shopping-Cart 之间的 has_cart 关系设为一对一，而不是一对多？
- 因为购物车不需要唯一标识
- 因为每个买家在任一时刻都只有一个活跃购物车 [correct]
- 因为一对一实现起来更简单
- 因为购物车在下单后就被删除
> 一个买家同一时间只维护一个活跃的购物会话（购物车）。订单会在买家生命周期里不断累积，购物车则是当前状态的实体——一个买家，一个活跃购物车。
```
